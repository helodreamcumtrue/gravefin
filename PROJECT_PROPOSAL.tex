\section{Higher-order goal \hfill \normalfont\small\textit{...secondary framing}}
This project aims to salvage abandoned digital intellectual capital and advance collaborative software engineering by creating an adversarial-safe, trustless marketplace for finishing incomplete codebases. While academic institutions and open-source ecosystems produce thousands of viable hackathon, capstone, and research projects that stall at 60--80\% completion, the immediate engineering objective is to translate \textbf{skin-in-the-game collateral and deterministic timeout enforcement} into a measurable, production-grade web application.

\section{Time-to-value \hfill \normalfont\small\textit{...primary heuristic}}
\begin{itemize}
    \item \textbf{Rapid Increment Delivery:} We deliver meaningful increments quickly by prototyping and validating the core end-to-end escrow state machine (Project Listing $\rightarrow$ Claim with Stake $\rightarrow$ Blind Delivery $\rightarrow$ Verification \& Collateral Release) within a short iteration window.
    \item \textbf{Fast Feedback over Perfection:} We eliminate subjective negotiation by substituting unstructured in-app chat with strict state machine transitions, prioritizing automated CI-backed tests and ledger consistency early to reduce release friction.
    \item \textbf{Measurable Outcomes:} Success is defined by what can be delivered and measured in the first iteration: zero double-claims, deterministic timeout enforcement via background jobs, and complete auditability across an append-only transaction ledger.
\end{itemize}

\section{Problem Statement}
Across university campuses and developer communities, hundreds of promising repositories are abandoned due to graduation, semester transitions, or shifting academic priorities. Common pain points include:
\begin{itemize}
    \item \textbf{Fragmentation \& Intellectual Capital Waste:} High-potential codebases (compilers, kernel modules, distributed databases, machine learning pipelines) sit idle in private or dead repositories rather than reaching deployment.
    \item \textbf{The Free-Rider \& Ghosting Problem:} When code is shared informally, prospective contributors frequently claim interest, request complete source access, and subsequently ghost---leaving original owners exploited and projects stalled.
    \item \textbf{Subjective Disputes \& Off-Platform Chaos:} Unstructured communication channels (DMs, emails, forums) lead to scope creep, unverified claims, harassment, and interpersonal conflict over project completion.
    \item \textbf{Financial \& Regulatory Overhead:} Implementing fiat monetary escrows requires burdensome PCI-DSS compliance, KYC identity verification, and banking rails that stifle low-friction student adoption.
\end{itemize}
\textbf{Why this matters now (contextual relevance):} In resource-constrained engineering environments, finishing existing, tested partial implementations is orders of magnitude more efficient than rebuilding from scratch. A trustless, points-based escrow marketplace introduces accountability without financial overhead.

\section{Proposed Solution \hfill \normalfont\small\textit{...Software Proposition}}

\subsection{Overview}
Build a web-based ``Gravefin'' escrow marketplace platform with the following core modules:
\begin{itemize}
    \item \textbf{Dead Codebase Registry:} Repository owners list incomplete codebases with metadata, completion percentage, tech tags, and a mandatory collateral stake requirement.
    \item \textbf{Anonymous Digger Identity Layer:} Cross-user identifiers are cryptographically decoupled from personal identities using deterministic pseudonyms (e.g., \texttt{Digger-1042}), preserving privacy and eliminating off-platform bias.
    \item \textbf{Skin-in-the-Game Escrow Machine:} Takers lock credit collateral into escrow upon owner approval, ensuring genuine commitment before source archives are decrypted and unlocked for download.
    \item \textbf{Append-Only Immutable Ledger:} Every credit allocation, stake lock, forfeiture, refund, and reputation adjustment is permanently recorded into an append-only audit trail (\texttt{LedgerEntry}).
    \item \textbf{Deterministic Timeout \& Slashing Engine:} Background cron services continuously inspect project deadlines, automatically penalizing inactive takers ($>14$ days) or unresponsive owners ($>7$ days).
    \item \textbf{Interactive Protocol Simulator:} A dedicated testing sandbox permitting administrators and evaluators to fast-forward time (+7d, +14d, +30d) and observe automated protocol state transitions in real time.
\end{itemize}

\subsection{Core workflow}
\begin{enumerate}
    \item \textbf{Listing:} Owner posts a project specifying completion stage (e.g., 65\%) and required taker stake (e.g., 150 credits).
    \item \textbf{Claiming:} Prospective Taker submits a claim request. System validates credit balance.
    \item \textbf{Escrow Lock:} Owner reviews applicant's reputation and approves. The platform locks the stake in escrow, changes project state to \texttt{ACTIVE}, and generates a 14-day inactivity deadline.
    \item \textbf{Blind Work \& Download:} Taker downloads the authorized project archive and implements required milestones without conversational interference.
    \item \textbf{Submission:} Taker uploads completed deliverables with implementation notes, transitioning the project to \texttt{SUBMITTED} and triggering a 7-day owner review window.
    \item \textbf{Resolution:} 
    \begin{itemize}
        \item \textit{Approval:} Stake is fully refunded to Taker, 100 platform completion credits are rewarded, and both parties gain +15 reputation.
        \item \textit{Owner Timeout ($>7$ days):} Automated cron automatically verifies the project, releasing escrow and awarding credits to the diligent Taker while docking Owner reputation.
    \end{itemize}
\end{enumerate}

\subsection{Operational constraints for an educational setting}
\begin{itemize}
    \item \textbf{Zero In-App Chat:} No chat or messaging UI is built. All interactions are atomic state transitions.
    \item \textbf{Client Usability:} Responsive web UI optimized for low-to-mid range devices via tokenized CSS without heavy client-side overhead.
    \item \textbf{Deployability:} Built on managed serverless primitives (Next.js serverless functions, Neon PostgreSQL, Vercel cron) for zero-maintenance continuous operation.
\end{itemize}

\subsection{Web architecture \hfill \normalfont\small\textit{...web-based solution}}
A 3-tier architecture with unified dynamic routing:
\begin{itemize}
    \item \textbf{Frontend:} Responsive UI for repository browsing, claiming, deliverable submission, and live ledger inspection.
    \item \textbf{Backend API:} Next.js Serverless API endpoints utilizing consolidated catch-all dispatchers (\texttt{/api/auth/[action]}, \texttt{/api/commitments/[...slug]}, \texttt{/api/projects/[...slug]}, \texttt{/api/users/[...slug]}).
    \item \textbf{Database:} Prisma ORM connected to Neon Serverless PostgreSQL with connection pooling and relational foreign-key integrity.
\end{itemize}

\subsection{CI/CD and fast delivery enabler}
\begin{itemize}
    \item \textbf{Automated Test Suite:} Single-command unified test runner (\texttt{scripts/test-all.js}) verifying database integrity, protocol transitions, and live HTTP API flows.
    \item \textbf{Continuous Deployment:} Integrated GitHub Actions and Vercel pipeline producing repeatable staging deployments on every commit.
\end{itemize}

\section{Evaluation Criterion \hfill \normalfont\small\textit{...measurable and attributable}}
We define success using measurable metrics tied directly to the core state machine.

\subsection{Primary evaluation metric}
\textbf{Escrow Resolution Efficiency (ERE):} The percentage of initiated project commitments that transition from \texttt{ACTIVE} to either a verified completion or an automated deterministic penalty without deadlocking.
\begin{itemize}
    \item \textbf{Target:} 100\% deterministic resolution (0 deadlocked or orphaned states).
    \item \textbf{Attribution:} Measured directly from database timestamps and ledger logs (\texttt{committedAt} vs. \texttt{resolvedAt}).
\end{itemize}

\subsection{Secondary evaluation metrics}
\begin{itemize}
    \item \textbf{Zero Double-Claims:} Concurrency safety ensuring no codebase can be simultaneously claimed by multiple takers (verified via transactional lock tests).
    \item \textbf{Audit Completeness:} Ratio of credit balance mutations to corresponding \texttt{LedgerEntry} records (Target: Exactly 1.0; zero unlogged balance changes).
    \item \textbf{Anonymity Leakage Rate:} Zero instances of user emails, hash passwords, or real names exposed in public API responses (verified via sanitization integration tests).
    \item \textbf{Reliability \& Performance:} 100\% build pass rate with 0 compilation errors and $<100$ ms API response times under standard loads.
\end{itemize}

\subsection{Pilot validation plan \hfill \normalfont\small\textit{...high-level}}
\begin{itemize}
    \item Deploy 6 distinct test personas (\texttt{Digger-1042} Owner, \texttt{Digger-2099} Active Taker, \texttt{Digger-3310} Flagged Contributor, \texttt{Digger-5501} Strike-Risk User) across 12 diverse dead codebases.
    \item Execute temporal simulations (+7 days, +14 days) via \texttt{/simulator} to validate automated slashing, stake refunding, and account banning.
    \item Recruit 15--20 student developers to submit and claim lab repositories over a 2-week pilot window.
\end{itemize}

\section{Scalability \hfill \normalfont\small\textit{...with foresight}}
The proposition scales in both theoretical and practical dimensions:
\begin{enumerate}

    \item \textbf{Operationally deployable (practically):} The system runs on cost-effective cloud primitives:

\end{enumerate}

\section{Engine availability heuristic}
A mature set of ``engines'' (tooling/services) is leveraged to ensure rapid, dependable implementation:
\begin{itemize}

    \item \textbf{Managed database:} Neon PostgreSQL with Prisma ORM for type-safe relational schemas.
    \item \textbf{Authentication approach:} Cryptographic HMAC SHA-256 session signatures with \texttt{HttpOnly} cookies.

\end{itemize}
By using these mature components, engineering effort is focused on workflow correctness, game-theoretic incentives, and auditability rather than reinventing underlying infrastructure.

\section{Risks and mitigations}
\begin{itemize}
    \item \textbf{Malicious Claim \& Disappearance:} Mandatory upfront credit stake collateral; 14-day timeout automatically forfeits stake to project owner and adds a permanent ghost strike.
    \item \textbf{Owner Bad-Faith Rejection:} Owners must provide concrete justification; if an owner ghosts, the 7-day review timeout auto-approves and releases funds to the taker.
    \item \textbf{Identity De-anonymization:} Strict API sanitization (\texttt{sanitizeUser}); database separates internal user credentials from public \texttt{Digger-XXXX} aliases.
    \item \textbf{Operational issues in pilot:} Zero-downtime serverless architecture with atomic database transactions preventing race conditions.
\end{itemize}

\section{Summary}
This project proposes \textbf{Gravefin}, a deployable web platform engineered to eliminate waste in student and developer software ecosystems. It adheres directly to course criteria by emphasizing rapid time-to-value through working iterations, implementing CI/CD to support frequent safe releases, and establishing measurable evaluation criteria (specifically Escrow Resolution Efficiency). It remains focused on engineering workflow, adversarial fault tolerance, and scalability readiness rather than research-driven novelty.
