1. What GraphQL is Doing in Gravefin

Gravefin is an escrow-backed, anonymous marketplace for reviving abandoned codebases. A single project entity does not exist in isolation; it sits at the intersection of a complex relational graph:

Project (Dead Code Specimen) ├──► Owner (e.g. Digger-1042) [Alias, Reputation, Strike Count] ├──► Forensic Autopsy [Cause of Decline, Difficulty, Health Score] ├──► Active Commitment [Staked Escrow, Delivery Deadlines] │ └──► Assigned Digger [Skin-in-the-Game Collateral] │ └──► Milestones & Handover Checklist Dual Sign-Off └──► Append-Only Ledger [Immutable Cryptographic Transaction Trail]

In standard REST architecture, loading a complete project page requires 4 to 5 separate HTTP round-trips (fetching the project, then the owner, then active commitments, then milestones, then ledger entries).

Key Role of GraphQL: GraphQL provides a single, unified query language enabling the frontend, external tools, or automated agents to fetch the exact nested graph of data needed in a single HTTP request, eliminating over-fetching and network waterfall latency.

Core Capabilities Provided

  • Graph Traversal: Query projects alongside their owners, commitments, autopsy health metrics, and tech tags in a single declaration.
  • Transactional State Mutations: Atomically lock collateral in escrow, record immutable audit entries, and transition project statuses.
  • Strict Anonymity & Privacy: Field-level resolvers automatically shield personal emails and GitHub tokens—counter-parties only ever receive pseudonymous aliases (e.g., Digger-1042).
  • Autonomous Cron Execution: Trigger deterministic 14-day taker inactivity and 7-day owner review timeouts via GraphQL mutations.

2. Implementation Architecture

The GraphQL layer is structured into 4 clean, modular tiers within the Next.js 14 Pages Router:

Layer File Path Responsibility
1. Type Definitions lib/graphql/typeDefs.js Strict GraphQL SDL declaring types, enums, inputs, queries, and mutations.
2. Resolvers lib/graphql/resolvers.js Executes Prisma queries, handles relational mapping, enforces transactions.
3. Serverless Route pages/api/graphql.js GraphQL Yoga v5 endpoint with auth session parsing and GraphiQL IDE.
4. In-App Explorer pages/graphql.jsx Interactive UI explorer with preset queries and execution timer.

The schema defines the exact contract between clients and the Gravefin database: 

type Project {
  id: ID!
  title: String!
  description: String!
  category: String!
  status: ProjectStatus!
  stakeRequired: Int!
  techTags: [String!]!
  revivalScore: Int
  revivalDetails: RevivalScoreDetails

  id: ID!

B. Relational Resolvers & Escrow Transactions (lib/graphql/resolvers.js)

When a nested field is requested, GraphQL executes field resolvers. When a mutation is triggered, it wraps database updates in an atomic Prisma transaction: 

// Atomic Escrow Staking Mutation
commitToProject: async (_, { projectId }, { currentUser }) => {
  if (!currentUser) throw new Error('Authentication required');
  if (currentUser.credits < project.stakeRequired) {
    throw new Error('Insufficient credits');
  }

  return await prisma.$transaction(async (tx) => {
    // 1. Append immutable ledger entry (-stakeRequired)
    await recordLedgerEntry({
      userId: currentUser.id,
      type: 'STAKE_LOCK',
      amount: -project.stakeRequired,
      relatedProjectId: project.id,
      notes: `Staked ${project.stakeRequired} credits in escrow`,
      tx
    });

    // 2. Create commitment record in PENDING_APPROVAL
    const commitment = await tx.commitment.create({
      data: {
        projectId: project.id,
        takerId: currentUser.id,
        stakeLocked: project.stakeRequired,
        status: 'PENDING_APPROVAL'
      }
    });

    // 3. Update project status
    await tx.project.update({
      where: { id: project.id },
      data: { status: 'PENDING_APPROVAL' }
    });

    return commitment;
  });
}
